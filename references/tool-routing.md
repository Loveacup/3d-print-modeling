# 按任务连接专业能力

当需要选择建模、表达、制造、项目管理或辅助判断工具时读取。先判断问题，再发现当前会话已有skills、工具和环境；此表提供典型入口，不是封闭白名单。工具名称只是可选入口，本公开包不包含所列技能、引擎或服务；仅在当前环境已发现且任务需要时读取其SKILL.md。读到skill不代表服务已连接、环境可执行或操作已授权。

需要补齐专业能力时，先读[配套技能上游与按需安装目录](upstream-skills.md)，选择当前任务需要的入口、版本和运行依赖；目录是来源导航，不是自动安装授权。本技能的维护仓库为[Loveacup/3d-print-modeling](https://github.com/Loveacup/3d-print-modeling)，技能自身问题归集到[该仓库Issues](https://github.com/Loveacup/3d-print-modeling/issues)；具体产品项目仍沿其既定归属。

## 建模基础路线

**新建常规3D打印功能件，以OpenSCAD为基础建模路线。** 支架、盒体、管夹、规则接口与重复结构等，适合用`.scad`中的变量、表达式和模块描述形体与尺寸关系，便于分享、重建和按需修改。选定后读取`openscad`入口，按任务深度使用其创建、修改或导出能力；基础路线不是每次必经的工具试用。

先看输入、要改变的内容与交付目标，再判断是否沿用这一基础：

- 已有可编辑源或用户明确指定工具，优先沿用；不为统一成OpenSCAD重建已有模型。
- 需要复杂曲面/圆角、直接实体编辑、可继续实体编辑的STEP或其他专有能力，可直接选择`cad`、适合的CAD/造型工具；无需先用OpenSCAD失败一次。明确指定Flowful时仍按其触发条件。
- 只有网格且只需局部改形，可保留网格主体做修改；需要可控尺寸关系时再重建相关部分。可以混合网格主体与参数化接口，不把导入STL的包装脚本称为恢复全部参数历史。
- 摆向、支撑或切片即可解决的问题，直接处理制造方案，不为了使用基础路线增加建模。工具暂不可用时诊断实际缺口或采用获准替代，不擅装环境。

OpenSCAD优先不等于参数化必选；何时值得建立参数关系见[参数化的用途与边界](geometry-validation.md#参数源与功能基准)。`.scad`是这条路线的可编辑源，导出的网格/3MF不是原始参数历史，也不自动成为带打印设置的可编辑切片工程。交付实际需要的源和派生产物，并核本次使用工具的真实导出能力。

## 能力入口

| 需要解决的问题 | 选择与衔接 |
| --- | --- |
| 目标拆解、任务推进、责任依赖、验收接手 | 有适用软件时读取其协作skill，如当前可发现的`linear-flow`，再选实际CLI/MCP/API；无接入按[项目内管理](project-organization.md#项目管理接入与本地后备)处理 |
| 新建常规功能件、OpenSCAD源/脚本，或选择OpenSCAD改模 | `openscad`；按上方[基础路线](#建模基础路线)选用，项目判断与切片仍由主技能统筹 |
| 更适合实体CAD的建模/编辑、STEP交付或保存后量测 | `cad`；执行前读其当前运行说明，沿用已有源并核所需导出能力 |
| 用户明确指定Flowful工具包、其CadQuery/GridfinityBin或扫描转口袋等能力 | `flowful-cad`；按该技能的具体触发条件，不因普通CAD/Gridfinity任务就启动 |
| 草图、爆炸图、机制/问题分析、产品或场景表达 | 按目的组合当前可用绘图、图像、渲染和模型工具；图源/证据身份准确。工程/制造图纸或二维投影视图（含未标尺寸的视图）按`engineering-drawing`的实际触发读取；意向草图、爆炸图和产品表达不全部强转为正投影PDF |
| 复杂方案对比、审阅页面或用户要求HTML | `answer-me-with-html`；不替代几何验证，不改成日常强制HTML |
| 平面轮廓、模板、加工DXF | `dxf`；保存后检查单位、尺寸与实体，用PDF预览不能替代加工文件 |
| 打印性、厚度/悬垂、姿态辅助分析 | `dfam-check`；核逐body有效样本与未测区域；某body空样本或厚度null时，退出0也不能证明全模型通过 |
| Orca本地切片与预设 | `gcode`；先核实际Orca与机料预设，不把合成预设测试当真实切片通过 |
| 明确请求本地Bambu profiles或Bambu CLI切片 | `bambu-studio-ai`；保留其已验证的本地范围和显式请求条件，其他上游脚本不随之获准 |
| 已有Bambu工程的核查、参数修改、保存后复切 | [切片与交付](slicing-and-delivery.md)，按当前可用合法入口；Bambu与Orca的CLI和版本能力分别核 |
| 用户要求向Bambu打印应用交接打印文件 | `bambu-labs`；依技能由用户选择打印机并启动，文件准备、上传和实际打印不是一回事 |
| 需要真实可采购标准件 | `step-parts`；核来源、规格与实际几何，示意占位不可冒充真实配件 |
| CNC、钣金、注塑或指定SendCutSend服务 | `dfm`、`sendcutsend`；按所选工艺适用，注塑规则不套作FDM默认 |
| 机器人结构、MoveIt语义或仿真描述 | 按实际输出选`urdf`、`srdf`、`sdf`；静态文件通过不等于运行或仿真通过 |
| 技能组合、建模路线、参数/切片候选或诊断的有限语义取舍 | 主动按需复用下节的`jev-sidekick`与`jev_evaluate`；先筛已知硬条件，不把服务设为项目依赖 |

能力未列出时主动研究已有合适工具。缺少运行条件则说明缺口、准备可做部分；新增安装、收费、上传或设备动作依实际授权，不在拒绝后换入口绕过。跨skill只传必要上下文，核返回产物、单位、版本与未完成项，不以退出码0代替任务验收。

## Jev按需判断副手

让主模型、Jev与专业工具各做擅长的事：主模型理解目标、研究和创造候选，Jev比较少量已描述候选的语义取舍，CAD/切片/测量工具执行和验证。**不只等卡住才用：**有清楚目标和可比候选，且第二意见可能减少错误选择或昂贵试错时，主动按需调用。这个合作方式不是每次必走的流程，能力列表也不是上限。

### 选择值得辅助的判断

| 当前取舍 | 可交给Jev的问题 | 仍由主模型与专业工具负责 |
| --- | --- | --- |
| 技能选择与组合 | 现有可用路线中，哪一种更贴合输入、编辑需求和交付目标 | 读取技能触发/权限、核运行条件；明确指定或规则已决定的路线直接沿用 |
| CAD/模型策略 | 局部改原生参数、组合特征、重建局部或网格修补，哪种值得先尝试 | 保留基线与获批域，创造候选、实现特征并独立检查最终几何；不为工具偏好迁移好用的模型 |
| 参数化与数值候选 | 已有参数关系或候选组中，哪组更符合功能、外观、可调性与制造取舍 | 单位、计算、边界约束、重算、几何量测与必要实测；不让Jev凭空给精确尺寸、公差或校准值 |
| 摆盘/分色/Z缝/支撑/切片 | 哪种联动方案最值得先切片，或已有同条件结果中哪种取舍更合目标 | 生效参数、机料兼容、真实刀路、整盘估算与实物验收；“值得试”不是“可打印通过” |
| 诊断与建议复核 | 哪项检查最能区分剩余原因，或已提出建议是否切题 | 保留反例与未知，执行检查再判原因；经验是否适用也可作有限比较 |

先用已知规则、算术和已有测试排除不合硬条件的选项，再比较语义取舍；只剩明确答案就直接推进。候选未做昂贵CAD/切片验证并不禁止预筛，但必须标出假设和未验证项，问“哪项值得先验证”，不能问成“哪项已经安全/合格”。大规模连续数值搜索和约束求解优先用脚本或适合的求解工具，Jev不替代计算。

### 构造小而可比的输入

读取当前发现的`jev-sidekick`，使用已提供的`jev_evaluate`，不因本参考而新增服务、SDK或配置。输入围绕当前决定而非整段会话：

- **目标与约束：** 当前要选什么、功能/外观/时间/成本取舍、不可改范围，以及相关授权与能力边界；用户未表达的优先级不能写成其承诺。
- **事实与候选：** 准确输入/版本、相关几何或工程摘要、既有检查；把实测、计算、引用、假设和未知分开。候选用稳定标签，说明差异、依据与代价，避免只给“A/B/C”或有暗示性的优劣名称。
- **判断问题：** 明确是选择先试路线、比较已验证结果还是下一项诊断。问一项能够由当前证据支持的有限判断，不要求开放式写CAD、生成参数表或计划全流程。

当前工具契约为显式有界`state`（≤12000 UTF-8字节）与`questions`：1–4个独立问题，每题有`id`、`instructions`、2–12个`options`，选项含`label`及必要`description`。候选可能不覆盖答案或证据不足时，提供“none-of-these/需补证据”出口。候选数量不构成设计空间上限；超出工具边界先按问题整理，不静默丢掉有意义方案或把不同批次概率拼成全局排名。

仅同一状态下可独立回答的问题合并调用；后题需要前题答案才能建立候选时分步处理，不假装独立。题外输入不传：凭据、私人模型/现场原件、完整日志或对话留本地，必要摘要去敏且有合法外传条件才发TypeSafe。工具不会替你读本地CAD、图像或完整工程。

### 采纳、验证与回退

返回的`choice`和`probabilities`用于候选间的相对建议；`confidence`只反映所给选项的概率分布集中程度，不是正确率、授权、结构安全或打印成功概率。不同问题/候选组的分数不可直接当通用质量分，亦不设统一审批或升级阈值。

主模型结合证据决定采纳、修订或否决；候选不足、歧义或相互冲突时补证据、改候选或自行判断，不为追求高分重问。几何、参数重算和切片的验证入口仍是[几何检查](geometry-validation.md)与[切片交付](slicing-and-delivery.md)。用户重大取舍、打印/上传/付费等授权不由Jev决定。

同一时间仅一次调用。`unavailable/busy/timeout/invalid_answer`等失败时继续可独立推进的工作，必要时说明缺口，不重试轰炸、擅装服务或换入口绕过限制。Jev建议无解释文本时，不杜撰它的推理；采纳理由是主模型结合实际证据作出的说明。

### 让收益大于调用成本

不在每轮或每个工具前自动调用。简单明确的事直接做；把有收益的独立问题合并，目标/约束、候选、证据和模型/工程版本仍一致时可复用已有判断，不必重问。相关输入变化或新反例出现就重新评估，不能拿旧结果当当前批准。

必要时在现有项目记录中简记：判断依据、候选与建议、是否采纳，以及后续实际结果。对加速/降成本的结论，应比较同类目标和验收口径下的总耗时与成本，包含准备摘要、API等待、主模型复核、验证、失败回退和返工；没有可比数据就只说预期收益。反馈按[每次使用回流](closeout.md)落到相关知识，单次合成测试不推广为生产收益。

官方依据：[Choice](https://docs.typesafe.ai/primitives/choice.md)、[confidence](https://docs.typesafe.ai/confidence.md)。官方支持的题数/选项或其他原语不等于当前封装已开放；运行时以当前工具schema及`jev-sidekick`为准。

## 当前运行条件与方法性反例

执行具体工具或解释检查范围时，核当前机器的真实配置与所选技能的最新运行说明；本包不提供另一台机器的安装记录、固定解释器或已通过声明，不为普通讨论加载安装历史。CAD、独立工具包和Bambu/OpenSCAD CLI未必共用入口。运行范围与历史记录冲突时核实际版本和能力，不悄悄放宽权限。

已知方法性反例：DfAM可能有body返回空样本/厚度null而整命令退出0；离散几何的零spread不等于误差为零；综合图纸命令可能PDF已生成但因DXF失败整体退出非零；切片preset兼容字段被改写不证明机器兼容。按实际产物、有效样本、错误和未测范围分别报告，不把历史反例写成当前环境已测试。

已测STEP/STL、静态适配器或单个样件不外推到其他导出、机器或实物；网格3MF不等于Bambu可编辑切片工程。几何、切片与实物验收仍回到[几何复核](geometry-validation.md)和[切片交付](slicing-and-delivery.md)。
